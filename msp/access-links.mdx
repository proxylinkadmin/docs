title: Access Links

Access links let you share access to a specific device with anyone - no ProxyLink account required on the recipient's side. Useful for giving a client access to their own server, or sharing a device with a contractor.

<Tip>
**Video tutorial:** [Share Device Access Without Accounts](https://proxylink.dev/tutorials/share-device-access-without-accounts) - 70 seconds from Share click to the client's one-click live session.
</Tip>

## Create an access link

1. Open the proxy link detail page for the device you want to share
2. Click **Share** → **Create Access Link**
3. Optionally set:
   - **Expiry date** - the link stops working after this date
   - **Link password** - asked on our own page before the link shows anything. Send it by a different channel than the URL.
   - **Allowed IPs** - addresses or ranges the link may be opened from. From anywhere else it answers as if it did not exist.
   - **Device password and username** (stored credentials) - pre-filled so the recipient connects automatically (RDP/SSH/HTTP). A **VNC** share needs nothing here: it authenticates with the device's own VNC password automatically, and the form does not ask for a VNC username.
4. Copy the generated URL and send it to the recipient

## How it works

The recipient opens the URL in a browser. If stored credentials are configured, the session opens immediately with no login prompt. If not, they see a connection dialog to enter credentials. A VNC share always connects with the device's VNC password - so rotating that password heals every existing share instead of breaking it.

The link works for SSH, RDP, VNC, and HTTP/HTTPS proxy links - any type of proxy link can be shared.

## File transfer on a shared link

- **SSH** - the share page shows a **Files** button beside **SSH Terminal**. It opens a file browser over SFTP: browse, upload, download, rename, delete and create folders. It signs in with the stored credentials if the link has them, otherwise the recipient enters an SSH username and password. They see the files that SSH user can see, nothing more. The device needs SFTP enabled, which is the default on most SSH servers.
- **VNC** - the **Files** button in the VNC toolbar, on Windows PCs deployed with the ProxyLink one-liner.
- **RDP** - file transfer is not offered on shared links.

A link gives file transfer to the same person it already gives a shell or the screen to. Expiry, revoking and pausing apply to it the same way.

## Locking a link

A link is a URL: by default whoever holds it gets in. Two optional locks change that, and you can use either or both.

**Link password**
- The recipient sees a page with one field. The device's name, its address and what the link opens are shown only after the right password.
- It is not the device's password. The device password is the one stored so the recipient is not asked for it; the link password is the one they must type.
- 6 to 72 characters, stored as a hash.
- Wrong guesses are limited: 10 from one address in 5 minutes, and 30 for one link in 15 minutes from everywhere together. After that the link refuses every password, the right one too, until the time passes. Setting a new password clears the count.

**Allowed IPs**
- Up to 20 addresses or ranges, IPv4 or IPv6, for example `203.0.113.10, 198.51.100.0/24`.
- Meant for an office or a vendor with a fixed address. Home and mobile connections change theirs, and that person would then be locked out.
- If the office also has IPv6, add its range too: a recipient who arrives over IPv6 is checked by that address.
- Empty means any address.

**Changing a lock** - use **Access rule** next to the link. Saving a change disconnects anyone using the link at that moment, and a web page opened through it stops on its next request. The owner, managers and engineers of the team can change it; employees cannot.

**What a lock does not cover** - a web link whose own access policy is *public* is reachable at its own address without the access link. To protect the page itself, change the [access policy](/proxy-links/access-policies) of the web link.

## Security

- **Single-device scope** - the recipient can only access the specific device the link was created for. They cannot navigate to other devices or see anything else in your ProxyLink account.
- **Expiry** - set an expiry date for time-limited access (e.g. for a contractor working on-site for a week). After expiry the link stops working, and any session still open through it is disconnected within a minute.
- **Revoke at any time** - delete the access link from the proxy link detail page. The URL stops working immediately and sessions already open through that link are disconnected. If one of them cannot be closed straight away you are told so on screen, and it is retried every minute until it is.
- **Pausing the device link also ends the share** - a paused proxy link is not connectable by anyone, the share page stops offering it, and sessions already open on it are disconnected.
- **Audit log** - every session initiated via an access link is logged in the audit log with the access link identifier, timestamp, and source IP.

## Use cases

- Give a hotel client access to their NVR camera stream without a ProxyLink account
- Share a server console with an external auditor for a limited time
- Let a client's IT person connect to a specific device without seeing your entire infrastructure
